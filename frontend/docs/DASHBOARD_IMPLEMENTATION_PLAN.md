# DASHBOARD_IMPLEMENTATION_PLAN

## 1) 핵심 강점 요약 및 설계 원칙

### 핵심 강점(현재/지향)
- **의회 맥락 특화 검색**: 일반 포털 검색이 놓치는 회의 맥락(본회의/상임위/의원발언/부록)을 한 화면에서 탐색.
- **미디어-텍스트 동시 탐색**: 자막, 발언자, 타임라인, 영상 딥링크가 연결된 실사용 중심 경험.
- **업무 역할별 정보 밀도 조정**: 일반 사용자와 사무처 담당자에게 다른 위젯/우선순위를 제공.

### 설계 원칙
1. **검색 우선(Search-first)**: 히어로 영역의 검색과 범위 탭을 최우선 인터랙션으로 배치.
2. **맥락 가시성(Context visibility)**: 위원회/회의유형/발언자/정당/지역 메타데이터를 항상 노출.
3. **점진적 고도화(Phased delivery)**: MVP에서 사용성 검증 후 품질(랭킹/개인화/AI요약) 고도화.
4. **신뢰성과 책임성**: AI 요약에는 명확한 면책문구와 원문 이동 경로를 제공.
5. **접근성/성능 기본 내재화**: 반응형·a11y·성능 기준을 Definition of Done에 포함.

## 2) 정보구조(IA) 및 화면 구성

## IA(탭 기반 검색 범위)
- 상단 통합 검색 + 범위 탭:
  - **전체**
  - **본회의**
  - **상임위**
  - **의원 발언**
  - **부록·자료**

탭은 검색 인덱스 스코프와 필터 프리셋을 동시에 제어:
- 전체: 모든 문서/자막/메타
- 본회의: plenary 문서 타입 우선
- 상임위: committee 세션 우선 + 위원회 필터 활성
- 의원 발언: speaker 중심 정렬/필터
- 부록·자료: 첨부/보도/보고서 타입 우선

## 화면 구성(헤더/히어로/3단 레이아웃)

### 헤더
- 좌측: 서비스명, 섹션 네비
- 우측: 프로필/알림/도움말 + **버전 배지(추가 완료)**

### 히어로
- 대형 검색 입력 + 범위 탭 + 추천 예시 질의
- placeholder 예시(순환 또는 랜덤):
  - `예: GTX 착공`
  - `예: 김경기도 의원 5분발언`

### 본문 3단 레이아웃
- **좌측 칼럼(탐색 강화)**
  - 위원회 아이콘 네비(색+형태 일관 규칙)
  - 의원 검색 필터: 가나다/정당/지역
- **중앙 칼럼(핵심 콘텐츠)**
  - 검색결과 카드 리스트(위원회 배지, 발언요약 2~3줄)
  - 워드클라우드(실시간 이슈 키워드)
- **우측 칼럼(개인화/운영 위젯)**
  - 카운팅 애니메이션 KPI
  - 로그인 역할 기반 위젯 전환(일반/사무처)

## 3) 기능 로드맵 (MVP → Phase 2 → Phase 3)

## MVP (4~6주)
- 상단 검색 + IA 탭 5종
- 좌측 기본 필터(위원회/의원/정당/지역)
- 중앙 카드형 결과(배지 컬러 시스템, 요약 2~3줄 원칙)
- 기본 워드클라우드(불용어 1차 적용)
- 우측 KPI + 카운팅 애니메이션(경량)
- 미디어 딥링크(시점 포함 URL) 공유

## Phase 2 (6~10주)
- 의회 용어 사전 기반 query expansion
- 랭킹 개선(BM25 + 필드가중치 + 최신성)
- 사용자 최근기록/저장검색
- 발언자 타임라인 + 주제 필터(예: 교통)
- AI 요약 품질 향상 + 면책문구 표준 노출

## Phase 3 (10주+)
- 역할별 대시보드 완성(사무처 운영 도구 확장)
- 추천 시스템(로그인 기반 개인화)
- 정책 키워드 추출 파이프라인 고도화(모델/사전 하이브리드)
- 검색 품질 자동평가 대시보드

---

## 4) 검색 품질 고도화 방안

### 4.1 의회 용어 사전
- 동의어/약어/표기 변형 사전 구축
  - 예: GTX, 광역급행철도 / 5분발언, 오분발언
- 고유명사 표준화(의원명, 위원회명, 지역구)

### 4.2 랭킹 전략
- 1단계: BM25 기반
- 2단계: 필드 가중치(제목 > 발언요약 > 본문 > 부록)
- 3단계: 최신성/인기도/클릭 로그 반영

### 4.3 필터 정교화
- 탭별 기본 필터 프리셋 제공
- 교차 필터(정당+지역+위원회+기간)
- 결과 없는 조합에 대한 필터 완화 제안

---

## 5) 개인화 전략

- 로그인 사용자 기준:
  - 최근 검색/최근 열람/북마크를 우선 위젯으로 노출
  - 관심 주제(교통/복지/예산 등) 기반 추천
- 역할 기반(일반/사무처):
  - 일반: 개인 추천, 최근 본 발언
  - 사무처: 처리대기, 민원연관, 품질점검 큐

---

## 6) 워드클라우드/정책 키워드 고도화

### 불용어 처리
- 기본 제외어: `의장`, `의원`, `이의`, `동의`, `말씀`, `질의`, `답변` 등
- 품사/빈도 기반 동적 불용어 업데이트

### 정책 키워드 추출 파이프라인
1. 자막/회의록 정제(normalize)
2. 형태소/명사구 추출
3. 정책 도메인 사전 매칭
4. 키워드 랭킹(TF-IDF + 기간가중)
5. 운영자 검수 큐(사무처)

---

## 7) 카드형 UI 시각 위계 원칙

- 위원회 배지 컬러 시스템:
  - 상임위별 고유 색상(명도 600 기준, 텍스트 대비 4.5:1 이상)
- 카드 정보 우선순위:
  1) 제목/주제
  2) 회의 메타(위원회/일시/발언자)
  3) **AI 요약 2~3줄** (초과시 말줄임)
  4) 원문/영상 이동 버튼

---

## 8) 우측 칼럼 위젯 전략

- KPI 카운팅 애니메이션
  - viewport 진입 시 1회 실행
  - `prefers-reduced-motion` 환경에서는 정적 표시
- 로그인 역할 기반 위젯 전환
  - 일반: 추천/최근기록
  - 사무처: 운영지표/품질알림/검수대기

---

## 9) AI 요약 면책문구(법적 디스클레이머)

표준 문구 제안:

> 본 요약은 AI가 자동 생성한 참고 정보입니다. 실제 발언의 법적·정책적 의미 판단은 원문 회의록 및 영상 확인을 우선해 주시기 바랍니다. 서비스 제공자는 요약의 완전성·정확성에 대해 법적 책임을 부담하지 않습니다.

적용 원칙:
- 카드/상세 모두 동일 문구 또는 축약+툴팁
- 원문 회의록/영상 바로가기 항상 함께 노출

## 10) 발언자 타임라인 / 미디어 싱크 / 공유 URL

### 발언자 타임라인
- 시간축에 발언 세그먼트 표시
- 주제 필터(예: 교통)로 세그먼트 하이라이트
- 클릭 시 플레이어 해당 시점으로 이동

### 미디어 싱크 및 딥링크
- URL 스키마 예시:
  - `/vod/{meetingId}?t=1320&speaker={speakerId}&topic=traffic`
- 공유 시 검색 컨텍스트(탭/필터) 보존
  - `scope=committee&committee=건설교통`

## 11) API/데이터 모델 제안

### 핵심 엔드포인트
- `GET /api/search`
  - query, scope, committee, speaker, party, region, from, to, page
- `GET /api/keywords/trending`
  - scope, period, stopwordProfile
- `GET /api/speakers`
  - q, initial(ㄱㄴㄷ), party, region
- `GET /api/timeline/{meetingId}`
  - speaker/topic/time-segment
- `GET /api/recommendations`
  - userId 기반 개인화 결과

### 데이터 필드(요약)
- SearchResult
  - id, title, scope, committee, speaker, party, region, meetingDate
  - summaryAi, summaryConfidence, videoUrl, timestamp, tags
- TimelineSegment
  - startSec, endSec, speakerId, topicTags, transcriptSnippet

## 12) 접근성/반응형/성능/보안 체크리스트

### 접근성
- 검색/탭/필터 키보드 접근 가능
- aria-label, role=tablist/tab 준수
- 색상 대비 4.5:1 이상

### 반응형
- 모바일: 1열(필터는 접이식)
- 태블릿: 2열
- 데스크톱: 3열 고정

### 성능
- 검색결과 가상 스크롤(조건부)
- 워드클라우드 서버 프리컴퓨트
- 코드 스플리팅/이미지 최적화

### 보안
- 검색 파라미터 검증/인코딩
- 역할 기반 위젯 API 권한 분리
- 감사 로그(관리 기능 접근)

---

## 13) 리스크 및 완화 전략

- **요약 신뢰도 리스크**: confidence score + 원문 링크 강제
- **검색 품질 편차**: 샘플 질의셋 회귀 테스트 도입
- **메타데이터 누락**: 수집 파이프라인에서 표준화 선행
- **역할별 권한 혼선**: RBAC 정책 문서화 + E2E 권한 테스트

---

## 14) 단계적 도입(Phased approach) + 데이터 표준화 선행 전략

1. **선행(공통)**: 데이터 표준 스키마 확정
   - 위원회/의원/정당/지역 코드셋 표준화
   - 발언 세그먼트 timestamp 규격 통일
2. MVP UI/검색 배포
3. 품질지표 계측(CTR, zero-result, 평균 체류시간)
4. 랭킹/개인화 고도화

## 15) 주차별 개발 일정 및 Definition of Done

### 주차별 일정(예시)
- 1주차: IA 확정, API 계약, 디자인 시안
- 2주차: 히어로 검색+탭, 좌측 필터 구현
- 3주차: 중앙 카드/우측 KPI/카운팅 애니메이션
- 4주차: 딥링크/타임라인 1차, 접근성 점검
- 5주차: 검색랭킹 1차/워드클라우드 개선
- 6주차: 개인화 1차/운영 안정화/문서화

### Definition of Done
- 기능 요구사항/수용기준 충족
- 단위/컴포넌트 테스트 통과
- 접근성 핵심 항목 점검 완료
- 성능 예산(초기 로딩/검색 응답) 충족
- 보안 점검(권한/입력검증) 완료

## 16) 구현 분류표 (즉시구현 가능 / 백엔드 선행 필요 / 정책검토 필요)

| 항목 | 분류 | 비고 |
|---|---|---|
| 헤더 버전 배지, 접근성 라벨 | 즉시구현 가능 | 프론트 단독 가능 |
| 히어로 검색 placeholder 예시 노출 | 즉시구현 가능 | 문구 정책만 확정하면 가능 |
| IA 탭 UI(전체/본회의/상임위/의원 발언/부록·자료) | 즉시구현 가능 | 실제 검색 스코프 연결은 API 필요 |
| 위원회 아이콘/배지 컬러 시스템 | 즉시구현 가능 | 디자인 토큰 필요 |
| 의원 가나다/정당/지역 필터 UI | 즉시구현 가능 | 실데이터 연동은 API 필요 |
| 워드클라우드 불용어 기본 적용 | 백엔드 선행 필요 | 인덱싱/전처리 파이프라인 필요 |
| 정책 키워드 추출 파이프라인 | 백엔드 선행 필요 | NLP 파이프라인/스케줄러 필요 |
| 역할 기반 위젯 전환(일반/사무처) | 백엔드 선행 필요 | 인증/권한 클레임 필요 |
| 카운팅 애니메이션 | 즉시구현 가능 | reduce-motion 대응 포함 |
| AI 요약 법적 디스클레이머 표준 문구 | 정책검토 필요 | 법무/운영 승인 필요 |
| 발언자 타임라인 주제 필터 | 백엔드 선행 필요 | 세그먼트+토픽 메타 필요 |
| 딥링크/공유 URL 전략 | 즉시구현 가능(1차) | 장기적으로 백엔드 로그연동 권장 |
